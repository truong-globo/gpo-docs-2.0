# Option type support matrix

Every option type carries a different set of settings. This page is the quick answer to "does this type have that?" — useful when you are choosing a type, and when a setting you expected is not where you thought.

Each type also has its own page with the full explanation. The links in the first column go there.

{% hint style="info" %}
**✓** means the setting exists on that type. **—** means it does not appear at all — not that it is hidden or off by default.

Some settings only become visible once something else is set. **Character counter** needs a character limit; **Advanced settings** needs a price. Those still show ✓ here, because the setting exists on the type.
{% endhint %}

## Reading the matrix

A few patterns are worth knowing, because they explain most "why is this missing?" questions.

<table><thead><tr><th width="290">Pattern</th><th>Reason</th></tr></thead><tbody><tr><td><strong>Conditional logic is on all 32 types</strong></td><td>Anything on the page can be shown or hidden, including headings, dividers, and sections. See <a href="../conditional-logic/README.md">Conditional logic</a></td></tr><tr><td>Static types have almost nothing else</td><td>They display something rather than collecting an answer, so there is no label to require and no value to limit</td></tr><tr><td><strong>Required</strong> is missing on Hidden field and Product links</td><td>Neither collects an answer that could be missing</td></tr><tr><td><strong>Placeholder</strong> exists on fewer types than <strong>Help text</strong></td><td>A placeholder sits inside a field. Types with no field to type in — swatches, buttons, checkboxes — have nowhere to put one</td></tr><tr><td>Character limits are on Text and Textarea only</td><td>They are the only free-text types. Number and Range slider limit by <strong>value</strong> instead</td></tr><tr><td><strong>Option values</strong> is on 13 types</td><td>Every type where you build a list. Nine of them share the same priced values table; <a href="../option-types/selection-types/font-picker.md">Font picker</a>, <a href="../option-types/selection-types/product-links.md">Product links</a>, <a href="../option-types/static-types/tabs.md">Tabs</a> and <a href="../option-types/input-types/dimension.md">Dimension</a> each have their own kind of rows, with no price column</td></tr><tr><td><strong>Price per value</strong> is on nine selection types</td><td>Those are the types with a priced values table. Font picker and Product links have values but no price column</td></tr><tr><td><strong>Column width</strong> and <strong>HTML class</strong> are on 30 types</td><td>Everything laid out on the page. Only <a href="../option-types/static-types/section.md">Section</a> and <a href="../option-types/input-types/hidden-field.md">Hidden field</a> are excluded — one is a container, the other renders nothing</td></tr></tbody></table>

## What conditional logic can and cannot reference

Every type can be **hidden or shown** by a rule. Not every type can be the thing a rule **looks at** — a divider has no answer to test.

The list of types that cannot be used as a condition source, and the operators available for each type that can, is on [Operators reference](../conditional-logic/operators-reference.md).

## POS support

Most types work in Shopify POS. Two do not:

<table><thead><tr><th width="290">Type</th><th>Why</th></tr></thead><tbody><tr><td><a href="../option-types/input-types/dimension.md">Dimension</a></td><td>Its formula pricing is not applied in POS</td></tr><tr><td><a href="../option-types/selection-types/product-links.md">Product links</a></td><td>It navigates to a storefront page, which POS has no equivalent of</td></tr></tbody></table>

## Plan availability

Some types and some settings are only on higher plans. The matrix above says what **exists in the app**; your plan decides what you can use.

Locked items are marked in the builder itself, which is the reliable check. See [Locked features](../plans/locked-features.md) and the **Pricing** page in the app.
